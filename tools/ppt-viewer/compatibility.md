# Legacy presentation compatibility

This viewer reads binary PowerPoint 97–2003 records directly in the browser. It does not convert documents, run an office suite, or upload files. DPS/DPT support means compatible OLE binary presentations, not every file carrying those extensions. The existing PPTX viewer handles modern PowerPoint containers.

Every opened deck is labeled a partial preview. The pinned parser recovers ordered text, basic drawing objects, master drawing content, and embedded picture records. Font sizes, colors, alignment, shape geometry, grouped objects, rotation, tables, and equations can differ from desktop applications. Some charts are saved EMF/WMF pictures; editable chart semantics are not available. Audio, video, animations, transitions, macros, and active OLE objects do not run.

## Corpus and provenance

- `fixtures/field-notes.ppt`: three owned slides generated by `fixtures/generate.py` and saved by LibreOffice as binary PPT. It includes text, a filled rectangle, an original PNG picture, a table, and rotated text. SHA-256: `891c895e8f5a1bc6dbe50f015a7c6de5296f743e7f07398001daabb2fd92ce9f`.
- [Public upstream legacy fixture](https://github.com/extend-hq/react-pptx/blob/222edd030e71d1772eaae11daac86dc80fb2720b/tests/fixtures/legacy/file-example-250kb.ppt): three saved slides, including master/background artwork, a chart preview, and a table. SHA-256: `1e4f6b07f0147358b4e6096d70ea7b1fb6d88bab18b2fb2a1b580185024ed158`. Used locally, not redistributed.
- Official [WPS Linux](https://linux.wps.cn/) 12.1.2.28080 package, `office6/mui/zh_CN/templates/wpp/all/green_for_general.dpt`: a genuine populated 12-slide template. Additional `party_culture_1.dpt`, `party_culture_2.dpt`, `personal_review.dpt`, and `team_report.dpt` each expose 12 saved slides. Used locally, not redistributed; no WPS application EULA was accepted.
- The same official package's `office6/asso_template/wps.dps` and `office6/mui/default/templates/newfile.dps`: genuine DPS defaults with zero saved slides. Other language defaults include a blank saved slide. These establish binary DPS container handling and the empty state, **not populated DPS fidelity**. An independently accessible populated DPS was not obtained; that compatibility remains unverified. No renamed PPT was used as DPS evidence.
- [Apache POI password-protected PPT](https://github.com/apache/poi/blob/trunk/test-data/slideshow/Password_Protected-hello.ppt): protection is detected and decryption is not attempted. Used locally, not redistributed.
- Additional owned local fixtures cover a portrait slide, 1,001 saved slides, an external hyperlink and literal script-like text, and a valid 111,633,408-byte OLE presentation containing a 105 MiB additional stream. The large stream exercises both source-size and OLE-stream handling without committing a disposable large binary.

## Observed browser output

Production Chromium, Firefox, and WebKit runs opened the owned binary PPT, the upstream PPT, and the official populated DPT. The owned PNG and filled rectangle render, and table text is recovered, but text size/color/alignment and rotated text differ from the LibreOffice reference. The upstream saved EMF chart remains visible in Chromium and Firefox after the legacy-only renderer patch, but is omitted in WebKit. Switching WebKit from OffscreenCanvas to a DOM canvas did not resolve that upstream metafile-rendering limitation. The WPS template's photograph and saved text are recovered, while its green geometric design and master typography differ substantially; master placeholder text can also appear. Opening a template is therefore not a claim of faithful WPS layout reproduction.

All three browser engines reached the last slide of the owned 1,001-slide PPT and opened the 111,633,408-byte presentation. Empty genuine DPS, protected PPT, malformed OLE data, and unrelated files produced distinct feedback. Desktop, 320-pixel width, portrait-slide, and short landscape focus layouts were checked. These runs observed no document-triggered external requests or page errors and zero remaining workers, object URLs, or canvases after closing the document.

## Parser and renderer boundaries

The parser is built reproducibly from public source pin `222edd030e71d1772eaae11daac86dc80fb2720b`; see `vendor/README.md` and `vendor/parser.patch`. There are no document-size, slide-count, OLE-entry-count, or edit-history quotas. Actual allocation, cycle, checked-arithmetic, recursion, decompression, and canvas protections remain.

The patched npm renderer is reserved for this binary viewer. Its unused DrawingML chart host and atlas imports are disconnected; the legacy parser emits only shape/image nodes, so saved EMF/WMF chart pictures remain on the retained image path. Do not reuse that patched package for a modern-format tool without restoring or isolating the chart implementation.

Only embedded raster/metafile bytes reach the renderer. URL assets, SVG, and embedded font sources are removed; links remain inactive. Missing fonts use local fallbacks. The parser worker terminates on completion, error, or cancellation. Closing or replacing a document releases renderer roots, object URLs, canvases, and pending work.
