## 在鑄造前檢查 NFT 中繼資料 JSON

選擇 **本機檔案**，即可檢查裝置上的個別 JSON 檔案或整個系列的資料夾。也可以直接選取 `1` 或 `42` 等以數字命名的檔案。工具會逐項回報無效的 JSON 和常見中繼資料問題，例如名稱空白、缺少圖片、描述無效或屬性格式有誤。使用 **待檢查** 找出需要修正的項目，或將完整報告下載為 JSON。

## 批次檢查代幣 URI

在 **代幣 URI** 中貼上中繼資料位址，每行一個。若系列使用數字編號，請選擇 **URI 範本**，使用含預留位置的位址，例如 `https://example.com/metadata/{id}.json`。設定起始 ID 和結束 ID，即可檢查包含兩端的範圍。十進位格式會直接使用輸入的 ID。**ERC-1155 十六進位** 依照 ERC-1155 的 `{id}` 替換規則，在前方補零，將每個 ID 寫成 64 個小寫十六進位字元。圖片連結等中繼資料值中的 `{id}` 也會被替換。

## 檢查 NFT 圖片和動畫連結

啟用 **檢查媒體能否存取**，即可檢查 `image` 和 `animation_url` 連結。若媒體以相對路徑引用，請選取整個本機資料夾。以 `/` 開頭的路徑會從所選資料夾的最上層解析。瀏覽器也能檢查 HTTP、IPFS 和 Arweave 資源。閘道錯誤、逾時或跨來源限制都可能讓連結無法確認。請在你使用的閘道或交易平台上再次查看這些連結。本機檔案會在瀏覽器中檢查，透過 URI 檢查時則會連線至對應的主機或閘道。

欄位定義和代幣 URI 替換規則請參閱 [OpenSea 中繼資料指南](https://docs.opensea.io/docs/metadata-standards)和 [ERC-1155 中繼資料規格](https://eips.ethereum.org/EIPS/eip-1155#metadata)。
