## 자막 변환기 소개

기존 자막 파일을 19가지 텍스트 자막 형식 간에 변환하거나 일반 텍스트 대본으로 내보낼 수 있습니다. 웹 영상에 사용할 SRT를 VTT로 바꾸고, ASS나 SSA의 대사를 SRT로 변환하고, 동영상 플랫폼에 올릴 자막을 준비하거나 여러 회차의 변환된 자막을 하나의 ZIP으로 모을 때 유용합니다. 변환은 브라우저에서 실행되며, 자막 파일과 붙여넣은 내용은 업로드되지 않습니다.

이 도구는 자막 텍스트와 표시 시간을 처리합니다. 파일을 선택하거나 자막을 붙여넣고, 출력 형식을 선택한 뒤 미리보기에서 결과를 확인하고 다운로드하세요. 기기에 있는 원본 파일을 변경하지 않고도 붙여넣은 내용을 수정해 다시 변환할 수 있습니다.

## 자막 변환 방법

1. **파일 선택**으로 자막 파일을 하나 이상 열거나, 입력 패널에 파일을 끌어놓거나, 편집기에 자막 텍스트를 붙여넣으세요. **예제 사용**을 선택하면 자막 항목 두 개가 있는 짧은 SRT 예제를 불러옵니다.
2. 일반적인 경우 **입력 형식**을 **자동 감지**로 두세요. 파일 이름에만 의존하지 않고 내용을 살펴 형식을 감지합니다. 형식이 모호한 파일은 원본 형식을 직접 선택하세요.
3. **출력 형식**을 선택하세요. 일반적인 웹사이트 자막 트랙에는 WebVTT를, 플레이어나 편집기에서 SRT 파일을 요구할 때는 SubRip을 선택하세요.
4. 파일 인코딩, 프레임 속도 또는 시간 오프셋을 바꾸려면 **변환 설정**을 여세요. 변환 전에 설정을 변경하세요.
5. **자막 변환**을 선택하세요. 결과에는 입력 형식과 출력 형식, 출력 파일 이름, 변환된 자막 항목 수가 표시됩니다.
6. **미리보기**와 **파일 내용**을 전환하며 확인한 뒤 변환된 텍스트를 복사하거나 파일을 다운로드하세요. 표에는 최대 100개의 자막 항목이 표시되며, 파일 내용과 다운로드에는 전체 결과가 포함됩니다.

**지우기**를 선택하면 페이지의 현재 입력과 결과가 삭제됩니다. 새 파일 묶음을 선택하면 이전 선택을 대체합니다. 변환기는 자막 기록을 보관하지 않으므로 보관할 결과는 다운로드하세요.

## 지원 형식과 출력 정밀도

아래 형식은 읽기 쉬운 대본으로 내보내는 용도의 TXT를 제외하고 모두 읽기와 쓰기를 지원합니다. 형식마다 시간을 저장하는 방식이 다르므로, 정밀도가 낮은 형식을 선택하면 해당 형식이 지원하는 단위로 타임스탬프를 반올림합니다.

| 형식                                 | 확장자    | 기록되는 시간 단위      |
| ------------------------------------ | --------- | ----------------------- |
| SubRip                               | `.srt`    | 밀리초                  |
| WebVTT                               | `.vtt`    | 밀리초                  |
| Advanced SubStation Alpha            | `.ass`    | 100분의 1초             |
| SubStation Alpha                     | `.ssa`    | 100분의 1초             |
| YouTube SubViewer                    | `.sbv`    | 밀리초                  |
| MicroDVD                             | `.sub`    | 영상 프레임             |
| SubViewer 2.0                        | `.sub`    | 100분의 1초             |
| SAMI                                 | `.smi`    | 밀리초                  |
| LRC 가사                             | `.lrc`    | 시작 시간은 100분의 1초 |
| Timed Text                           | `.ttml`   | 밀리초                  |
| Distribution Format Exchange Profile | `.dfxp`   | 밀리초                  |
| YouTube SRV3                         | `.srv3`   | 밀리초                  |
| YouTube transcript XML               | `.xml`    | 밀리초 정밀도의 초 단위 |
| MPL2                                 | `.mpl`    | 10분의 1초              |
| Spruce Subtitle, 텍스트 형식         | `.stl`    | 영상 프레임             |

TTML 입력은 호환되는 iTT 파일도 지원합니다. DFXP는 TTML 계열에 속합니다. TTML로 내보낼 때 플랫폼별 프로필, 레이아웃, 스타일 규칙이 모두 재현되지는 않습니다.

여기서 `.sub` 확장자는 텍스트 기반 MicroDVD 또는 SubViewer를 뜻합니다. 바이너리 VobSub는 다른 형식입니다. 마찬가지로 지원되는 `.stl` 형식은 텍스트 기반 Spruce STL이며, 바이너리 EBU STL과는 다릅니다. 이 확장자만으로 형식을 구분하기 어려울 때는 전체 형식 이름을 보고 선택하세요.

## SRT, VTT, ASS, 일반 텍스트 중에서 선택하기

**SRT**는 동영상 플레이어, 편집기 또는 업로드 양식에서 SubRip 자막을 요구할 때 유용합니다. **VTT**는 HTML 동영상의 텍스트 트랙에 사용되는 형식으로, 웹 전용 자막 항목 설정도 담을 수 있습니다. 둘 사이를 변환하면 자막 텍스트와 밀리초 단위의 표시 시간을 유지하면서 파일 구문을 다시 구성합니다.

번호가 있는 SRT 자막 항목은 밀리초 앞에 쉼표를 사용합니다.

```text
1
00:00:01,250 --> 00:00:03,500
Hello, world!
```

같은 자막을 WebVTT로 표현하면 파일 헤더가 생기고 타임스탬프에 소수점을 사용합니다.

```text
WEBVTT

00:00:01.250 --> 00:00:03.500
Hello, world!
```

**ASS와 SSA**는 다음에 사용할 애플리케이션에서 해당 형식을 요구할 때 유용한 교환 형식입니다. 지원되는 굵게, 기울임꼴, 밑줄 서식은 이를 표현할 수 있는 형식 사이에서 유지될 수 있습니다. 글꼴, 화면 위치, 그리기 명령, 가라오케 애니메이션과 기타 고급 표현 기능은 단순화되며, 읽을 수 있는 대사 없이 그래픽만 있는 ASS 이벤트는 건너뜁니다. 변환기는 제작된 애니메이션이나 레이아웃을 재현하기보다 읽을 수 있는 자막을 만드는 데 중점을 둡니다.

**TXT**는 타임스탬프나 스타일 없이 읽을 수 있는 대사를 추출합니다. 미리보기에는 시간 정보 표 대신 내보낸 텍스트가 표시됩니다. TXT 내보내기는 자막 표시 시간을 새로 만들거나, 음성을 텍스트로 변환하거나, 대사의 언어를 번역하지 않습니다.

## 파일 인코딩과 올바른 문자 표시

자동 파일 디코딩은 UTF-8을 사용하며, 바이트 순서 표시로 UTF-16이 확인되면 UTF-16을 사용합니다. 오래된 파일에서 글자가 깨져 보이거나 파일을 디코딩할 수 없다면 원래 인코딩을 선택하세요. UTF-8과 UTF-16을 직접 지정하는 옵션 외에도 Windows-1252, Windows-1251, GB18030, Big5, Shift_JIS, EUC-KR 등을 선택할 수 있습니다.

예를 들어 GB18030으로 저장된 중국어 자막에는 GB18030을, 오래된 애플리케이션에서 만든 일본어 파일에는 Shift_JIS를 선택해 보세요. 인코딩은 기존 바이트를 읽는 방식을 바꾸며, 그 의미를 번역하지는 않습니다. 인코딩을 바꾼 뒤에는 다시 변환하세요. 다운로드되는 자막 파일은 입력 인코딩과 관계없이 UTF-8을 사용합니다.

## 표시 시간과 프레임 속도 조정

### 모든 자막을 앞당기거나 늦추기

시간 오프셋의 단위는 밀리초입니다. `1500`을 입력하면 모든 자막이 1.5초 늦게 표시되고, `-500`을 입력하면 0.5초 일찍 표시됩니다. `00:00:01.250`에 시작하는 자막에 각각 적용하면 시작 시간이 `00:00:02.750`과 `00:00:00.750`이 됩니다.

오프셋은 시작 시간과 종료 시간을 함께 이동하므로, 타임라인의 시작점에 걸리기 전까지는 표시 시간이 유지됩니다. 전체가 0초 이전으로 이동한 자막은 제거되고, 일부만 0초 이전으로 이동한 자막은 0초부터 시작합니다. 오프셋은 일정한 시간 차이를 보정합니다. 영상이 진행됨에 따라 시간 차이가 달라지는 자막 트랙은 보정하지 못합니다.

### 프레임 기반 타임스탬프에 프레임 속도 사용하기

MicroDVD와 Spruce STL은 영상 프레임을 사용하므로, 프레임 속도에 따라 프레임이 경과 시간으로 환산되는 방식이 달라집니다. TTML에도 프레임 기반 시간 정보가 포함될 수 있습니다. 입력을 해석하는 데 필요한 경우 원본 영상의 프레임 속도(예: `23.976`, `24`, `25`, `29.97`)를 사용하세요.

입력 형식에 프레임 속도가 포함되어 있으면 해당 값이 우선 적용됩니다. 프레임 기반 출력에서는 선택한 설정에 따라 기록되는 프레임 속도가 결정됩니다. 이 설정을 바꿔도 일반적인 SRT나 VTT의 시계 형식 타임스탬프가 비례 조정되지는 않습니다. 프레임 기반 타임스탬프를 해석하거나 기록하는 방식이 달라집니다.

### 반올림과 종료 시간이 없는 경우 이해하기

SRT와 VTT는 밀리초 정밀도를 유지합니다. ASS, SSA, SubViewer, LRC는 100분의 1초로, MPL2는 10분의 1초로, 프레임 기반 출력은 프레임 단위로 반올림합니다. 매우 짧은 자막도 반올림 후에 표시 시간이 0보다 크게 유지됩니다. 미리보기에는 반올림 전 입력 타임스탬프가 아니라 내보내는 형식의 시간 정보가 표시됩니다.

LRC에는 종료 시간 없이 시작 시간만 있을 수 있습니다. 종료 시간이 없으면 다음으로 나오는 서로 다른 시작 시간을 사용하며, 마지막 자막은 2초간 표시합니다. LRC 내보내기는 원래 자막 사이의 공백 시간이나 겹치는 종료 시간을 유지할 수 없으며, 여러 줄의 자막은 한 줄의 가사가 됩니다. QuickTime Text는 타임라인 마커를 사용합니다. SAMI와 QuickTime은 시간이 구분되는 각 지점에서 겹치는 자막의 텍스트를 합쳐 다시 구성할 수 있으므로, 결과의 자막 구간 수가 달라질 수 있습니다.

## 일괄 변환과 ZIP 다운로드

여러 파일을 선택하거나 끌어놓으면 같은 출력 형식과 설정으로 변환할 수 있습니다. 파일 이름 메뉴에서 결과를 선택해 확인하세요. 변환할 수 없는 파일에는 개별 오류가 표시되며, 성공한 결과는 각각 다운로드할 수 있습니다.

파일 두 개 이상을 성공적으로 변환하면 **모두 ZIP으로 다운로드**로 결과를 모을 수 있습니다. 압축 파일에는 변환에 성공한 결과만 포함됩니다. 표시된 오류를 확인하고 필요에 따라 입력 형식이나 인코딩을 조정한 뒤 남은 파일을 다시 변환하세요.

출력 파일 이름은 원본의 기본 이름을 유지하고 선택한 확장자를 사용합니다. 예를 들어 `episode01.srt`는 `episode01.vtt`가 됩니다. 여러 결과의 이름이 같아지면 ` (2)`와 같은 접미사를 붙여 ZIP 안에서 구분합니다. 여기서 ZIP은 다운로드 옵션입니다. 입력으로는 자막 파일 자체를 선택하세요.

## JSON, CSV, TSV 데이터 교환

JSON은 밀리초 단위의 `start`와 `end` 값, `text` 문자열이 있는 자막 객체 배열을 사용합니다.

```json
[
  { "start": 1250, "end": 3500, "text": "Hello, world!" },
  { "start": 4000, "end": 6000, "text": "Another caption." }
]
```

또한 `segments` 배열이 있는 Whisper 스타일 JSON도 읽을 수 있으며, 이 경우 각 세그먼트의 `start`와 `end` 값은 초 단위입니다. 이는 별도의 입력 규칙이며, 일반 JSON 내보내기는 계속 밀리초를 사용합니다.

CSV와 TSV는 `start`, `end`, `text` 열 이름을 사용합니다. 입력 시간은 밀리초 단위의 숫자 또는 시계 형식 타임스탬프일 수 있습니다. CSV는 쉼표, 따옴표 또는 줄바꿈이 있는 필드를 따옴표로 감싸고, TSV는 열 사이에 탭을 사용합니다. 두 형식 모두 내보낼 때 밀리초 단위의 숫자를 기록합니다. 자막을 스프레드시트나 다른 자막 처리 작업으로 옮길 때 이 형식을 사용하세요.

## 자주 묻는 질문

### 미리보기와 다운로드한 텍스트가 다르게 보이는 이유는 무엇인가요?

미리보기 표에는 읽을 수 있는 자막 텍스트와 대상 형식의 시간 정보가 표시됩니다. 파일 내용에는 헤더, 번호, 구분자, 지원되는 서식 구문을 포함한 실제 직렬화된 파일이 표시됩니다. 표에 처음 100개 자막만 표시되더라도 다운로드에는 직렬화된 전체 내용이 포함됩니다.

### 스타일이나 위치가 바뀐 이유는 무엇인가요?

형식마다 스타일을 표현하는 방식이 다릅니다. 지원되는 기본 서식은 표현할 수 있는 범위에서 유지되지만, 고급 스타일, 웹 자막 위치, 애니메이션, 플랫폼 메타데이터는 완전히 재현되지 않습니다. 파일 내용 보기에서 내보낸 결과를 확인하고, 실제로 사용할 플레이어나 편집기에서 테스트하세요.

### 동영상이나 이미지 트랙에서 자막을 추출할 수 있나요?

기존 텍스트 자막 파일이 필요합니다. 동영상에 내장된 자막 트랙은 먼저 추출하세요. 이미지 기반 PGS/SUP와 VobSub/IDX 트랙을 텍스트로 바꾸려면 OCR이 필요하며, 바이너리 EBU STL에는 해당 형식을 읽을 수 있는 자막 편집기가 필요합니다.

### 형식 사양은 어디서 확인할 수 있나요?

파일 구문과 플랫폼 요구 사항은 [WebVTT 사양](https://www.w3.org/TR/webvtt1/), [TTML 사양](https://www.w3.org/TR/ttml2/), [YouTube에서 지원하는 자막 형식](https://support.google.com/youtube/answer/2734698)을 참고하세요.
