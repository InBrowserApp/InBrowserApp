## 關於字幕轉換器

在 19 種定時文字格式之間轉換現有字幕檔案，或匯出純文字逐字稿。常見用途包括將 SRT 轉成網頁影片使用的 VTT、將 ASS 或 SSA 對白轉成 SRT、為影片平台準備字幕，以及將多集轉換後的字幕收集到同一個 ZIP 中。轉換作業會在瀏覽器中執行；字幕檔案和貼上的內容都不會上傳。

本工具處理的是字幕文字及其時間。選擇檔案或貼上字幕、選取輸出格式，再透過預覽檢查結果後下載。你可以編輯貼上的內容並重新轉換，不會改動裝置上的原始檔案。

## 如何轉換字幕

1. 選取**選擇檔案**來開啟一個或多個字幕檔案、將檔案拖曳到輸入面板，或將字幕文字貼到編輯器中。**試用範例**會載入一段含有兩段字幕的簡短 SRT 範例。
2. 一般使用時，將**輸入格式**保留為**自動偵測**。偵測功能會檢查內容，不只依據檔名判斷。如果檔案格式無法明確判定，請自行選取來源格式。
3. 選擇**輸出格式**。一般網站的字幕軌可選 WebVTT；如果播放器或編輯器要求 SRT 檔案，則選 SubRip。
4. 需要其他檔案編碼、影格率或時間偏移時，開啟**轉換設定**。請在轉換前變更這些設定。
5. 選取**轉換字幕**。結果會顯示來源與輸出格式、輸出檔名，以及轉換的字幕段數。
6. 在**預覽**與**檔案內容**之間切換，然後複製轉換後的文字或下載檔案。表格最多顯示 100 段字幕；檔案內容與下載檔案都包含完整結果。

**清除**會移除頁面上的目前輸入與結果。選擇新的一批檔案會取代先前的選取項目。轉換器不會保留字幕歷史紀錄，因此請下載想保留的結果。

## 支援的格式與輸出精確度

下表所有項目都支援讀取與寫入，只有 TXT 是供閱讀的逐字稿匯出格式。不同格式儲存時間的方式不同；選擇精確度較低的格式時，時間戳記會四捨五入到該格式支援的單位。

| 格式                                 | 副檔名    | 寫入的時間精確度         |
| ------------------------------------ | --------- | ------------------------ |
| SubRip                               | `.srt`    | 毫秒                     |
| WebVTT                               | `.vtt`    | 毫秒                     |
| Advanced SubStation Alpha            | `.ass`    | 百分之一秒               |
| SubStation Alpha                     | `.ssa`    | 百分之一秒               |
| YouTube SubViewer                    | `.sbv`    | 毫秒                     |
| MicroDVD                             | `.sub`    | 影片影格                 |
| SubViewer 2.0                        | `.sub`    | 百分之一秒               |
| SAMI                                 | `.smi`    | 毫秒                     |
| LRC 歌詞                             | `.lrc`    | 開始時間精確至百分之一秒 |
| Timed Text                           | `.ttml`   | 毫秒                     |
| Distribution Format Exchange Profile | `.dfxp`   | 毫秒                     |
| YouTube SRV3                         | `.srv3`   | 毫秒                     |
| YouTube 逐字稿 XML                   | `.xml`    | 秒，精確至毫秒           |
| MPL2                                 | `.mpl`    | 十分之一秒               |
| Spruce Subtitle，文字格式            | `.stl`    | 影片影格                 |
| QuickTime Text                       | `.qt.txt` | 毫秒                     |
| JSON                                 | `.json`   | 以毫秒為單位的數值       |
| CSV                                  | `.csv`    | 以毫秒為單位的數值       |
| TSV                                  | `.tsv`    | 以毫秒為單位的數值       |
| 純文字逐字稿，僅供匯出               | `.txt`    | 不含時間戳記             |

TTML 輸入也接受相容的 iTT 檔案。DFXP 屬於 TTML 家族。匯出 TTML 時，不會完整重現各平台特有的設定規範、版面配置或樣式規則。

此處的 `.sub` 副檔名可能代表文字格式的 MicroDVD 或 SubViewer。二進位 VobSub 是另一種格式。同樣地，這裡支援的 `.stl` 格式是文字格式的 Spruce STL，而非二進位 EBU STL。這些副檔名無法明確判定格式時，請依完整名稱選擇。

## 如何選擇 SRT、VTT、ASS 與純文字

影片播放器、編輯器或上傳表單要求 SubRip 字幕時，**SRT** 是實用的選擇。**VTT** 是 HTML 影片文字軌使用的格式，也可以攜帶網頁專用的字幕段落設定。在兩者之間轉換時，會保留字幕文字與毫秒時間，並重新建立檔案語法。

有編號的 SRT 字幕段落會在毫秒前使用逗號：

```text
1
00:00:01,250 --> 00:00:03,500
Hello, world!
```

相同字幕在 WebVTT 中會包含檔案標頭，時間戳記則使用小數點：

```text
WEBVTT

00:00:01.250 --> 00:00:03.500
Hello, world!
```

接下來使用的應用程式要求 **ASS 與 SSA** 時，這兩種格式是實用的交換選項。支援的粗體、斜體與底線格式，可以在能表達這些樣式的格式之間保留。字型、畫面位置、繪圖指令、卡拉 OK 動畫及其他進階呈現效果會簡化；沒有可讀對白的圖形 ASS 事件則會略過。轉換器著重於可讀的字幕，不會完整重現原先設計的動畫或版面配置。

**TXT** 會擷取可讀的對白，不含時間戳記或樣式。其預覽會顯示匯出的文字，而非時間表格。TXT 匯出不會自行產生字幕時間、將語音轉成文字，或翻譯說話內容。

## 檔案編碼與文字可讀性

自動檔案解碼會使用 UTF-8；若位元組順序標記指出為 UTF-16，則使用 UTF-16。處理較舊的檔案時，如果文字顯示異常或無法解碼檔案，請選擇原始編碼。除了明確指定 UTF-8 與 UTF-16，還可選擇 Windows-1252、Windows-1251、GB18030、Big5、Shift_JIS 及 EUC-KR。

例如，已知以 GB18030 儲存的中文字幕可以嘗試選用 GB18030；來自舊版應用程式的日文檔案則可以嘗試 Shift_JIS。編碼會改變現有位元組的讀取方式，不會翻譯其含義。選取其他編碼後，請重新轉換。無論輸入使用何種編碼，下載的字幕檔案都使用 UTF-8。

## 調整時間與影格率

### 讓所有字幕提前或延後

時間偏移以毫秒為單位。`1500` 會讓所有字幕延後 1.5 秒；`-500` 則會讓字幕提前半秒顯示。對於從 `00:00:01.250` 開始的字幕，這兩項設定會分別產生 `00:00:02.750` 和 `00:00:00.750`。

偏移會同時移動開始與結束時間，在碰到時間軸起點前會保留原本的持續時間。偏移後完全位於零點之前的字幕會移除；只有一部分跨越零點的字幕會從零開始。偏移可修正固定的延遲，無法修正隨影片播放而逐漸變化的字幕時間偏差。

### 為以影格為基準的時間戳記設定影格率

MicroDVD 與 Spruce STL 使用影片影格，因此影格率會決定影格如何對應到經過的時間。TTML 也可能包含以影格為基準的時間。需要解讀這類輸入時，請使用來源影片的影格率，例如 `23.976`、`24`、`25` 或 `29.97`。

如果輸入格式提供內嵌的影格率，會優先使用該影格率。輸出以影格為基準的格式時，選取的設定會決定寫入的影格率。變更這項設定不會按比例調整一般 SRT 或 VTT 的時鐘時間戳記；它會改變以影格為基準的時間戳記的解讀或寫入方式。

### 了解四捨五入與缺少結束時間的處理方式

SRT 與 VTT 保留毫秒精確度。ASS、SSA、SubViewer 與 LRC 會四捨五入到百分之一秒；MPL2 四捨五入到十分之一秒；以影格為基準的輸出則四捨五入到影格。非常短的字幕在四捨五入後仍會保有正的持續時間。預覽會反映匯出格式的時間，而非顯示尚未四捨五入的輸入時間戳記。

LRC 可以只提供開始時間而沒有結束時間。缺少的結束時間會使用下一個不同的開始時間；最後一段字幕則持續兩秒。LRC 匯出無法保留原始字幕間隔及重疊的結束時間，多行字幕也會合併成單行歌詞。QuickTime Text 使用時間軸標記；SAMI 與 QuickTime 可以在每個時間邊界將重疊字幕重建為合併文字，因此結果的字幕段數可能不同。

## 批次轉換與 ZIP 下載

選擇或拖入多個檔案，即可使用相同的輸出格式與設定進行轉換。從檔名選單選取一項結果來檢查。無法轉換的檔案會各自保留錯誤訊息，成功的結果則仍可個別下載。

至少有兩個檔案轉換成功時，**全部下載為 ZIP**會將這些輸出打包。壓縮檔只包含成功的轉換結果。請檢查顯示的錯誤、依需要調整輸入格式或編碼，再重新轉換剩餘的檔案。

輸出檔名會保留來源的基本檔名，並使用所選的副檔名：例如 `episode01.srt` 會變成 `episode01.vtt`。如果多個結果的名稱相同，會加上 ` (2)` 之類的後綴，以區分 ZIP 中的檔案。ZIP 在這裡是下載選項；輸入時請選擇字幕檔案本身。

## JSON、CSV 與 TSV 資料交換

JSON 使用由字幕物件組成的陣列，每個物件包含以毫秒為單位的 `start` 與 `end` 值，以及 `text` 字串：

```json
[
  { "start": 1250, "end": 3500, "text": "Hello, world!" },
  { "start": 4000, "end": 6000, "text": "Another caption." }
]
```

讀取時也接受包含 `segments` 陣列的 Whisper 風格 JSON，其中各段落的 `start` 與 `end` 值以秒為單位。這是另一種輸入慣例；一般 JSON 匯出仍使用毫秒。

CSV 與 TSV 使用 `start`、`end` 與 `text` 作為欄位名稱。輸入時間可以是毫秒數值或時鐘時間戳記。CSV 會以引號包住包含逗號、引號或換行的欄位；TSV 則使用定位字元分隔欄位。兩種格式匯出時都會寫入毫秒數值。需要將字幕移到試算表或其他字幕處理流程時，可以使用這些格式。

## 常見問題

### 為什麼預覽與下載的文字看起來不同？

預覽表格顯示可讀的字幕文字，以及目標格式的時間。檔案內容則顯示實際序列化後的檔案，包括標頭、編號、分隔符號及支援的格式語法。即使表格只顯示前 100 段字幕，下載檔案仍包含完整的序列化內容。

### 為什麼樣式或位置改變了？

各格式的樣式模型不同。只要目標格式能表達，支援的基本格式就會保留；進階樣式、網頁字幕段落位置、動畫及平台中繼資料則不會完整重現。請使用檔案內容檢視來檢查匯出結果，並在實際要使用的播放器或編輯器中測試。

### 這能從影片或圖片字幕軌擷取字幕嗎？

請先準備現有的文字字幕檔案。影片內嵌的字幕軌需要先行擷取。圖片格式的 PGS/SUP 與 VobSub/IDX 字幕軌需要透過 OCR 轉成文字；二進位 EBU STL 則需要使用能讀取該格式的字幕編輯器。

### 哪裡可以查閱格式規格？

檔案語法與平台要求請參閱 [WebVTT 規格](https://www.w3.org/TR/webvtt1/)、[TTML 規格](https://www.w3.org/TR/ttml2/)及 [YouTube 支援的字幕格式](https://support.google.com/youtube/answer/2734698)。
