## JSON Patch 적용 방법

첫 번째 편집기에 원본 JSON 문서를 붙여넣고, 두 번째 편집기에 RFC 6902 JSON Patch 배열을 붙여넣으세요. **패치 적용**을 선택하면 업데이트된 JSON을 미리 보고 복사할 수 있습니다. 패치를 만들려면 [JSON 차이 경로](../json-diff-path/)에서 원본과 수정된 문서를 비교한 뒤 **JSON Patch** 출력을 복사하세요. 패치를 만들 때 사용한 것과 동일한 원본 문서에 적용하세요.

## JSON Patch 예제

원본 문서에는 상태와 태그가 하나씩 들어 있습니다.

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

이 패치는 원래 상태를 확인한 뒤 상태를 바꾸고 태그를 하나 추가합니다.

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

결과는 `{"status":"published","tags":["api","release"]}`입니다.

## 지원되는 작업과 JSON Pointer 구문

- `add`는 객체 멤버를 추가하거나 덮어쓰고, 배열에 항목을 삽입하거나, 루트의 문서 전체를 교체합니다.
- `remove`는 기존 값을 삭제합니다. `replace`는 기존 값을 새 값으로 교체합니다.
- `move`는 `from` 포인터에 있는 기존 값을 꺼내 `path`에 삽입합니다. `copy`는 원본과 별개의 복사본을 삽입합니다.
- `test`는 문서를 수정하지 않고 `path`의 값이 지정된 `value`와 같은지 확인합니다.

경로에는 RFC 6901 JSON Pointer를 사용합니다. 배열 인덱스는 0부터 시작하므로 `/tags/0`은 첫 번째 태그를 가리킵니다. 배열에 값을 추가하는 작업에서 `/tags/-`는 값을 배열 끝에 덧붙입니다. 객체 키 안에 있는 슬래시는 `~1`, 물결표는 `~0`으로 표시하세요. 예를 들어 `/a~1b`는 `a/b` 키를 가리킵니다. 빈 경로 `""`는 문서 전체를, `/`는 키가 빈 문자열인 멤버를 가리킵니다.

## JSON Patch 작업이 실패하는 이유

작업은 배열에 나열된 순서대로 실행되며, 각 작업은 앞선 작업이 반영된 문서에 적용됩니다. 대상이 없거나 배열 인덱스가 범위를 벗어나거나 `test`의 값이 다르면 처음 실패한 작업을 표시하고 처리를 중단합니다. 패치 전체가 성공한 경우에만 JSON 미리보기가 표시됩니다. 빈 패치 배열 `[]`은 원본 문서를 그대로 반환합니다.

패치는 브라우저에서 로컬로 적용됩니다. 원본 JSON과 패치는 브라우저 내부에 남습니다.
