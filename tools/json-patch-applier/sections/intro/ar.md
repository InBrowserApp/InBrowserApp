## كيفية تطبيق JSON Patch

ألصق مستند JSON الأصلي في المحرر الأول، ومصفوفة عمليات JSON Patch وفق RFC 6902 في المحرر الثاني. اختر **تطبيق التصحيح** لمعاينة JSON المعدّل ونسخه. لإنشاء تصحيح، قارن المستندين الأصلي والمعدّل في أداة [مسارات فروق JSON](../json-diff-path/) وانسخ مخرجات **JSON Patch**. طبّق التصحيح على المستند الأصلي نفسه.

## مثال على JSON Patch

يحتوي المستند الأصلي على حالة ووسم واحد.

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

يتحقق هذا التصحيح من الحالة الأصلية ثم يحدّثها ويضيف وسمًا في النهاية.

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

النتيجة هي `{"status":"published","tags":["api","release"]}`.

## العمليات المدعومة وصيغة JSON Pointer

- تنشئ العملية `add` عضوًا في كائن أو تكتب فوق عضو موجود، أو تُدرج عنصرًا في مصفوفة، أو تستبدل المستند كله عند المسار الجذري.
- تحذف العملية `remove` قيمة موجودة. وتستبدل العملية `replace` قيمة موجودة بقيمة جديدة.
- تنقل العملية `move` قيمة موجودة من المؤشر `from` وتُدرجها عند `path`. أما العملية `copy` فتُدرج نسخة مستقلة.
- تتحقق العملية `test` من أن القيمة عند `path` تساوي القيمة المحددة في `value` وتترك المستند كما هو.

تتبع المسارات صيغة JSON Pointer وفق RFC 6901. تبدأ فهارس المصفوفات من الصفر، لذلك يشير `/tags/0` إلى الوسم الأول، ويضيف `/tags/-` قيمة في نهاية المصفوفة عند تنفيذ عملية إضافة إليها. استخدم `~1` للشرطة المائلة و`~0` لعلامة التلدة داخل مفتاح في كائن. مثلًا، يشير `/a~1b` إلى المفتاح `a/b`. يشير المسار الفارغ `""` إلى المستند بأكمله، بينما يشير `/` إلى عضو مفتاحه فارغ.

## أسباب فشل عمليات JSON Patch

تُنفَّذ العمليات بترتيب ورودها في المصفوفة، وتعمل كل عملية على نتيجة العمليات السابقة. إذا لم يكن الهدف موجودًا، أو تجاوز الفهرس حدود المصفوفة، أو فشلت مطابقة القيمة في عملية `test`، تحدد الأداة أول عملية فشلت وتتوقف. تُعرض معاينة JSON بعد نجاح التصحيح بأكمله فقط. تعيد مصفوفة التصحيح الفارغة `[]` المستند الأصلي.

يطبّق المتصفح التصحيح محليًا. يبقى مستند JSON الأصلي والتصحيح في متصفحك.
