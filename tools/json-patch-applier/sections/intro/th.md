## วิธีใช้ JSON Patch

วางเอกสาร JSON ต้นฉบับในช่องแรกและวางอาร์เรย์ JSON Patch ตาม RFC 6902 ในช่องที่สอง เลือก **ใช้แพตช์** เพื่อดูตัวอย่างและคัดลอก JSON ที่อัปเดตแล้ว หากต้องการสร้างแพตช์ ให้เปรียบเทียบเอกสารต้นฉบับกับเอกสารที่แก้ไขใน [ตัวเปรียบเทียบเส้นทาง JSON](../json-diff-path/) แล้วคัดลอกผลลัพธ์จากแท็บ **JSON Patch** จากนั้นใช้แพตช์กับเอกสารต้นฉบับชุดเดิม

## ตัวอย่าง JSON Patch

เอกสารต้นฉบับมีสถานะและแท็กหนึ่งรายการ

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

แพตช์นี้จะตรวจสอบสถานะเดิม อัปเดตสถานะ และเพิ่มแท็กที่ท้ายอาร์เรย์

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

ผลลัพธ์คือ `{"status":"published","tags":["api","release"]}`

## การดำเนินการที่รองรับและไวยากรณ์ JSON Pointer

- `add` สร้างหรือเขียนทับสมาชิกของออบเจ็กต์ แทรกรายการในอาร์เรย์ หรือแทนที่ทั้งเอกสารที่ตำแหน่งราก
- `remove` ลบค่าที่มีอยู่ ส่วน `replace` แทนที่ค่าที่มีอยู่ด้วยค่าใหม่
- `move` นำค่าที่มีอยู่จากตัวชี้ `from` ไปแทรกที่ `path` ส่วน `copy` จะแทรกสำเนาที่เป็นอิสระจากต้นฉบับ
- `test` ตรวจสอบว่าค่าที่ `path` เท่ากับ `value` ที่ระบุหรือไม่ โดยไม่แก้ไขเอกสาร

เส้นทางใช้ไวยากรณ์ JSON Pointer ตาม RFC 6901 ดัชนีอาร์เรย์เริ่มที่ศูนย์ ดังนั้น `/tags/0` คือแท็กแรก และ `/tags/-` จะเพิ่มค่าที่ท้ายอาร์เรย์เมื่อการดำเนินการนั้นเพิ่มรายการ ใช้ `~1` แทนเครื่องหมายทับและ `~0` แทนเครื่องหมายทิลเดอในคีย์ของออบเจ็กต์ เช่น `/a~1b` ใช้อ้างถึงคีย์ `a/b` เส้นทางว่าง `""` ใช้อ้างถึงทั้งเอกสาร ส่วน `/` ใช้อ้างถึงสมาชิกที่มีคีย์ว่าง

## ทำไมการดำเนินการของ JSON Patch จึงล้มเหลว

การดำเนินการจะทำตามลำดับในอาร์เรย์ โดยแต่ละรายการใช้ผลจากรายการก่อนหน้า หากไม่พบเป้าหมาย ดัชนีอาร์เรย์เกินขอบเขต หรือค่าที่ตรวจด้วย `test` ไม่ตรงกัน เครื่องมือจะเน้นจุดที่ล้มเหลวครั้งแรกแล้วหยุดทำงาน ตัวอย่าง JSON จะแสดงเมื่อแพตช์ทำงานสำเร็จทั้งหมดเท่านั้น อาร์เรย์แพตช์ว่าง `[]` จะคืนเอกสารต้นฉบับ

เบราว์เซอร์จะใช้แพตช์ในเครื่องของคุณ เอกสาร JSON ต้นฉบับและแพตช์จะอยู่ในเบราว์เซอร์
