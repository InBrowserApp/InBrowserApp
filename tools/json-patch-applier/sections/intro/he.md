## איך מחילים JSON Patch

הדביקו את מסמך ה-JSON המקורי בעורך הראשון ומערך JSON Patch לפי RFC 6902 בעורך השני. בחרו **החלת תיקון** כדי להציג ולהעתיק את ה-JSON המעודכן. כדי ליצור תיקון, השוו בין המסמך המקורי למסמך המעודכן בכלי [השוואת JSON לפי נתיב](../json-diff-path/) והעתיקו את פלט ה-**JSON Patch**. החילו אותו על אותו מסמך מקורי.

## דוגמה ל-JSON Patch

המסמך המקורי מכיל סטטוס ותגית אחת.

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

התיקון בודק את הסטטוס המקורי, מעדכן אותו ומוסיף תגית בסוף המערך.

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

התוצאה היא `{"status":"published","tags":["api","release"]}`.

## פעולות נתמכות ותחביר JSON Pointer

- הפעולה `add` יוצרת שדה באובייקט או מחליפה שדה קיים, מוסיפה פריט למערך או מחליפה את כל המסמך בנתיב השורש.
- הפעולה `remove` מוחקת ערך קיים. הפעולה `replace` מעדכנת ערך קיים לערך חדש.
- הפעולה `move` מעבירה ערך קיים מהנתיב `from` אל `path`. הפעולה `copy` מכניסה ליעד עותק עצמאי.
- הפעולה `test` בודקת אם הערך בנתיב `path` שווה לערך שסופק בשדה `value` ומשאירה את המסמך ללא שינוי.

הנתיבים משתמשים בתחביר JSON Pointer לפי RFC 6901. האינדקסים במערך מתחילים באפס. לכן `/tags/0` מפנה לתגית הראשונה, ואילו `/tags/-` מוסיף ערך בסוף המערך בפעולת הוספה. בתוך מפתח של אובייקט, השתמשו ב-`~1` עבור לוכסן וב-`~0` עבור טילדה. לדוגמה, `/a~1b` מפנה למפתח `a/b`. הנתיב הריק `""` מפנה למסמך כולו, והנתיב `/` מפנה לשדה שהמפתח שלו ריק.

## למה פעולת JSON Patch נכשלת

הפעולות רצות לפי סדר הופעתן במערך, וכל פעולה מקבלת את התוצאה של הפעולות שקדמו לה. אם היעד חסר, האינדקס מחוץ לגבולות המערך או שהערך שנבדק בפעולת `test` אינו תואם, הכלי מסמן את הפעולה הראשונה שנכשלה ועוצר. תצוגה מקדימה של JSON מופיעה רק לאחר שכל הפעולות בתיקון הצליחו. מערך תיקון ריק `[]` מחזיר את המסמך המקורי.

הדפדפן מחיל את התיקון באופן מקומי. ה-JSON המקורי והתיקון נשארים בדפדפן.
