## JSON Patch を適用する方法

最初の入力欄に元の JSON ドキュメントを、2 番目の入力欄に RFC 6902 準拠の JSON Patch 配列を貼り付けます。**パッチを適用**を選ぶと、更新後の JSON を確認してコピーできます。パッチを作成するには、[JSON差分パス](../json-diff-path/)で変更前と変更後のドキュメントを比較し、**JSON Patch** の出力をコピーします。作成時に使ったものと同じ元のドキュメントに適用してください。

## JSON Patch の例

元のドキュメントには、ステータスと 1 つのタグが含まれています。

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

このパッチは元のステータスを確認して更新し、タグを 1 つ追加します。

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

結果は `{"status":"published","tags":["api","release"]}` です。

## 対応する操作と JSON Pointer の書き方

- `add` はオブジェクトのメンバーを追加または上書きする、配列に要素を挿入する、あるいはルートでドキュメント全体を置き換える操作です。
- `remove` は既存の値を削除します。`replace` は既存の値を新しい値に置き換えます。
- `move` は `from` が指す既存の値を取り出し、`path` で指定された位置に移します。`copy` は元の値とは独立したコピーを挿入します。
- `test` は `path` の値が指定された `value` と等しいかを確認します。ドキュメントは変更しません。

パスの指定には RFC 6901 の JSON Pointer を使います。配列のインデックスは 0 から始まるため、`/tags/0` は最初のタグを指します。配列に値を追加する操作では、`/tags/-` を指定すると末尾に追加できます。オブジェクトのキー内のスラッシュは `~1`、チルダは `~0` と書きます。たとえば `/a~1b` はキー `a/b` を指します。空のパス `""` はドキュメント全体を、`/` はキーが空文字列のメンバーを指します。

## JSON Patch の操作が失敗する理由

操作は配列に並んだ順に実行され、各操作にはそれ以前の変更が反映されたドキュメントが渡されます。対象が存在しない場合、配列のインデックスが範囲外の場合、または `test` の値が一致しない場合には、最初に失敗した操作を表示して処理を停止します。JSON のプレビューはパッチ全体が成功したときに表示されます。空のパッチ配列 `[]` を適用すると元のドキュメントがそのまま返ります。

パッチはブラウザー内で適用されます。元の JSON とパッチはブラウザー内に留まります。
