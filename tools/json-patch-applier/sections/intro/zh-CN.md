## 如何应用 JSON Patch

将原始 JSON 文档粘贴到第一个编辑区，再将符合 RFC 6902 的 JSON Patch 数组粘贴到第二个编辑区。点击 **应用补丁**，即可预览和复制更新后的 JSON。如需生成补丁，可在 [JSON 路径差异对比](../json-diff-path/) 中比较原始文档和修改后的文档，再复制 **JSON Patch** 输出。应用补丁时，请使用生成补丁时的同一份原始文档。

## JSON Patch 示例

原始文档包含一个状态字段和一个标签。

```json
{
  "status": "draft",
  "tags": ["api"]
}
```

以下补丁会先检查原始状态，再更新状态并追加一个标签。

```json
[
  { "op": "test", "path": "/status", "value": "draft" },
  { "op": "replace", "path": "/status", "value": "published" },
  { "op": "add", "path": "/tags/-", "value": "release" }
]
```

结果为 `{"status":"published","tags":["api","release"]}`。

## 支持的操作与 JSON Pointer 语法

- `add` 创建或覆盖对象成员、插入数组元素，或替换根路径处的整个文档。
- `remove` 删除已有的值。`replace` 用新值替换已有的值。
- `move` 从 `from` 指向的位置取出已有的值，并插入到 `path` 指定的位置。`copy` 则插入该值的独立副本。
- `test` 检查 `path` 对应的值是否等于提供的 `value`，且不修改文档。

路径使用 RFC 6901 定义的 JSON Pointer。数组索引从零开始，因此 `/tags/0` 指向第一个标签。在向数组添加值时，`/tags/-` 表示追加到末尾。对象键中的斜杠写成 `~1`，波浪号写成 `~0`。例如，`/a~1b` 指向键 `a/b`。空路径 `""` 指向整个文档，而 `/` 指向键名为空字符串的成员。

## JSON Patch 操作失败的原因

补丁按数组顺序执行，每项操作都基于前面操作执行后的文档。如果目标路径不存在、数组索引越界，或 `test` 的实际值与预期值不同，工具会标出第一项失败的操作并停止处理。整个补丁应用成功后，才会显示 JSON 预览。空补丁数组 `[]` 会返回原始文档。

补丁在浏览器中本地应用。原始 JSON 和补丁均留在浏览器中。
