## バイナリ API データを調べる

CBOR と MessagePack は、構造化データをコンパクトに表現するバイナリシリアライズ形式です。この変換ツールでは、API レスポンス、WebSocket メッセージ、キャッシュされた値を JSON として確認したり、デバッグ用のバイナリデータを JSON から作成したりできます。すべてブラウザー内で処理し、入力をアップロードしたり保存したりしません。

## JSON をエンコード、バイト列をデコード

バイナリ形式と変換方向を選択します。エンコードする場合は JSON を入力し、出力の表記形式として 16 進数、Base64、Base64URL のいずれかを選びます。デコードする場合はバイト列を貼り付け、入力のエンコード形式を選びます。入力のエンコード形式を変更すると、エディター内のテキストをその形式で解釈し直します。

エンコード時は JSON ファイル、デコード時は生の `.cbor`、`.msgpack`、`.bin` ファイルを開けます。16 進数や Base64 などのエンコード済みテキストはエディターに貼り付けてください。変換後は表示されたテキストをコピーするか、結果をダウンロードできます。バイナリのダウンロードには実際のバイト列が含まれ、再び読み込むことができます。

## 値を保持し、制限を理解する

整数リテラルは、各形式が対応する 64 ビットの範囲内ですべての桁を保持します。バイナリフィールド、CBOR タグ、MessagePack 拡張など、JSON で表せない値は明示的な型付きラッパーで表示します。これらのラッパーをバイナリに戻す場合は拡張 JSON を有効にしてください。ラッパーのキーと同じ名前を使う通常の JSON オブジェクトを扱う場合は、無効のままにしてください。

たとえば、拡張 JSON を有効にして `{"id":{"$integer":"9007199254740993"},"data":{"$binary":"AQI="}}` をエンコードすると、正確な整数と 2 バイトのバイナリデータになります。

1 回の変換で扱う値は 1 つで、入力の上限は 1 MiB です。「整形済み JSON のバイト数」は元の入力ではなく、画面に表示する整形後の JSON を数えます。再エンコードでは対応する値を保持しますが、マップの順序やバイナリエンコードの選択が変わる場合があります。ラッパーの構文や非対応の型については、上の「形式と型の保持」を開いてください。
