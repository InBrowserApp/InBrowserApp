## בדיקת נתונים בינריים של API

CBOR ו-MessagePack הם פורמטים בינריים קומפקטיים לסריאליזציה של נתונים מובנים. אפשר להשתמש בממיר כדי לבדוק תגובות API, הודעות WebSocket או ערכים ממטמון בתור JSON, או כדי ליצור נתונים בינריים מתוך JSON לצורך ניפוי שגיאות. כל העיבוד מתבצע בדפדפן; הקלט אינו מועלה או נשמר.

## קידוד JSON או פענוח בתים

יש לבחור את הפורמט הבינרי ואת כיוון ההמרה. לקידוד, יש להזין JSON ולבחור Hex, Base64 או Base64URL לפלט. לפענוח, יש להדביק בתים ולבחור את קידוד הקלט שלהם. שינוי קידוד הקלט מפרש מחדש את הטקסט שכבר נמצא בעורך.

אפשר לפתוח קובץ JSON בעת קידוד, או קובץ גולמי מסוג `.cbor`, `.msgpack` או `.bin` בעת פענוח. טקסט מקודד, כגון Hex או Base64, יש להדביק בעורך. לאחר ההמרה אפשר להעתיק את הטקסט המוצג או להוריד את התוצאה. הורדות בינריות מכילות את הבתים עצמם וניתן לייבא אותן שוב.

## שימור ערכים והבנת המגבלות

ערכים מילוליים של מספרים שלמים שומרים על כל הספרות בטווח 64 סיביות שהפורמט תומך בו. ערכים ש-JSON אינו יכול לייצג, כגון שדות בינריים, תגיות CBOR והרחבות MessagePack, מופיעים כאובייקטים מפורשים עם ציון טיפוס. יש להפעיל JSON מורחב כדי לקודד אובייקטים אלה חזרה לבינרי; יש להשאירו כבוי עבור אובייקטי JSON רגילים שבמקרה משתמשים במפתחות טיפוס מיוחדים.

לדוגמה, כאשר JSON מורחב מופעל, `{"id":{"$integer":"9007199254740993"},"data":{"$binary":"AQI="}}` מקודד מספר שלם מדויק ושני בתים בינריים.

כל המרה מטפלת בערך אחד, עם מגבלת קלט של 1 MiB. המונה בתים ב-JSON המעוצב סופר את ה-JSON המוצג בעיצוב קריא ולא את הקלט המקורי. קידוד מחדש שומר על הערכים הנתמכים אך עשוי לשנות את סדר המפות או את בחירת הקידוד הבינרי. אפשר לפתוח את ״פורמטים ושימור טיפוסים״ לעיל כדי לקרוא על תחביר האובייקטים עם ציון הטיפוס ועל טיפוסים שאינם נתמכים.
