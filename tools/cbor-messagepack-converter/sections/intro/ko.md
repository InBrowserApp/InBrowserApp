## 바이너리 API 페이로드 검사

CBOR와 MessagePack은 구조화된 데이터를 위한 간결한 바이너리 직렬화 형식입니다. 이 변환기로 API 응답, WebSocket 메시지 또는 캐시된 값을 JSON으로 검사하거나 디버깅을 위해 JSON에서 바이너리 페이로드를 생성할 수 있습니다. 모든 처리는 브라우저에서 이루어지며 입력 데이터는 업로드되거나 저장되지 않습니다.

## JSON 인코딩 또는 바이트 디코딩

바이너리 형식과 변환 방향을 선택하세요. 인코딩하려면 JSON을 입력하고 출력 형식으로 Hex, Base64 또는 Base64URL을 선택하세요. 디코딩하려면 바이트를 붙여넣고 해당 입력 인코딩을 선택하세요. 입력 인코딩을 변경하면 편집기에 이미 있는 텍스트를 새 인코딩으로 해석합니다.

인코딩할 때는 JSON 파일을, 디코딩할 때는 원시 `.cbor`, `.msgpack` 또는 `.bin` 파일을 여세요. Hex 또는 Base64 같은 인코딩된 텍스트는 편집기에 붙여넣어야 합니다. 변환한 다음 표시된 텍스트를 복사하거나 결과를 다운로드하세요. 바이너리 다운로드에는 실제 바이트가 포함되므로 다시 가져올 수 있습니다.

## 값 보존 및 제한 사항 이해

정수 리터럴은 형식이 지원하는 64비트 범위 내에서 모든 자릿수가 보존됩니다. 바이너리 필드, CBOR 태그, MessagePack 확장처럼 JSON으로 표현할 수 없는 값은 명시적인 타입 래퍼로 표시됩니다. 이 래퍼를 다시 바이너리로 인코딩하려면 확장 JSON을 활성화하세요. 우연히 래퍼 키를 사용하는 일반 JSON 객체에는 확장 JSON을 꺼 두세요.

예를 들어 확장 JSON을 활성화하면 `{"id":{"$integer":"9007199254740993"},"data":{"$binary":"AQI="}}`는 정확한 정수와 바이너리 바이트 2개를 인코딩합니다.

한 번에 값 하나를 변환하며 입력 제한은 1 MiB입니다. 서식이 적용된 JSON 바이트 수는 원본 입력이 아닌, 화면에 보기 좋게 서식이 적용되어 표시된 JSON을 기준으로 계산합니다. 다시 인코딩하면 지원되는 값은 보존되지만 맵 순서나 바이너리 인코딩 방식이 달라질 수 있습니다. 래퍼 구문과 지원되지 않는 타입은 위의 “형식 및 타입 보존”을 열어 확인하세요.
