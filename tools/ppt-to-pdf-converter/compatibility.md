# Legacy PPT / DPS PDF export

Accepts PowerPoint 97–2003 binary presentations (`.ppt`, `.pps`, `.pot`) and
compatible binary WPS Presentation documents/templates (`.dps`, `.dpt`).
The selected file must contain a valid current presentation, not merely a
matching extension. Modern ZIP-based PowerPoint files use the separate PPTX
converter. Password-protected files and empty presentations are rejected.

The self-hosted LibreOffice WebAssembly runtime exports static PDF pages with
selectable supported text and native graphics. It keeps slide order, dimensions,
and hidden slides. Font substitution and advanced effects can differ from the
original application; the user previews the exact downloadable bytes. This is
not a guarantee of pixel-identical Office output. Notes, comments, animation,
transitions, media playback, macros and signature verification are excluded.

Preflight follows the current persist directory instead of counting obsolete
slides left by incremental saves. Live slide/master picture references must
point to present, consistent OfficeArt BLIP records. PNG/JPEG payloads must
decode successfully before the office engine starts. Native metafile rendering
remains the office engine's responsibility. The engine's slide count and the
PDF page count must match the source's live slide list; PDF dimensions must be
positive and finite. Detected corruption or unavailable content yields no
successful download. These checks detect known loss; they cannot prove fidelity
for every undocumented or advanced presentation feature.

Files and engine state stay in disposable browser workers. Engine workers and
native pthreads block fetch, XMLHttpRequest, WebSocket and EventSource requests;
assets are downloaded separately before initialization. Macros are disabled at
load time. Closing, replacing or canceling terminates conversion and releases
the preview. There is no product file-size or slide-count quota. Genuine memory
and browser capability failures are reported when the browser can surface them.

Only this converter's pages require COOP/COEP headers. Entering or leaving them
uses a full document navigation so the browser applies those headers. The engine
is loaded after file selection and initially transfers about 90 MB including
fallback fonts. See `runtime/NOTICE.md` and `fonts/README.md` for pinned sources,
licenses, library-mode initialization and asset packaging.

## Representative sources

- `fixtures/field-notes.ppt`: original three-slide artwork with saved text,
  shapes, an original PNG, a table, and rotation. Its source generator lives
  alongside the original fixture in the PPT viewer.
- `fixtures/languages.ppt`, generated by `fixtures/languages.py`: original
  CJK, Arabic, Hebrew, Thai, Devanagari, Greek, Cyrillic and Vietnamese text;
  a hidden middle slide and a final slide with explicit order markers.
- Genuine WPS `green_for_general.dpt`: twelve populated slides from the public
  WPS Office package's Chinese presentation templates. Used locally only;
  third-party artwork is not redistributed.
- Genuine native WPS `wps.dps`: empty presentation from the same package,
  tested as an error. A populated native DPS sample has not been independently
  verified; renamed PPT files are not evidence of native DPS fidelity.
- Additional original portrait, external-link/literal-text, 1,001-slide and
  111,633,408-byte presentations, plus modified missing-picture, damaged-record,
  broken-raster, malformed-container and unrelated-file cases.
- Apache POI's public password-protected presentation, used locally only.

## Verification

Production-bundle and deployed-browser results are recorded in the pull request.
The owned fixtures are also covered by unit tests for current-edit resolution,
image references, corruption, worker lifecycle, cancellation, stale results,
preview failure and download cleanup. Compressed assets are checked for exact
reassembly and the deployment host's per-file size constraint.
